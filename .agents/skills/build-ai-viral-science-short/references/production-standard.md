# AIバズ科学Shorts 制作標準

新規制作、大幅な編集変更、字幕・音声・SEO・QC判断が必要なときに読む。

## 成功条件

- 尺は25〜35秒。
- 感情曲線は `矛盾 → 好奇心 → 納得 → スケール拡大 → ツッコミ`。
- 無音でも5〜8秒以内に現象と固有名詞が分かる。
- AI映像は感情と動き、一次資料とRemotion図解は事実を担当する。
- 1本につき、検証する主変数は最大3つにする。

## 推奨ストーリー

| 区間 | 役割 | 要件 |
|---|---|---|
| 0〜3秒 | 結果先出し | 最も不可能に見える瞬間と大見出しを同時に見せる |
| 3〜8秒 | 名称 | 未知の対象名を大きく出す |
| 8〜12秒 | 疑問 | 視聴者の誤解や疑問を女性の一言で代弁する |
| 12〜22秒 | 仕組み | 男性の落ち着いた説明と単純な図解。専門語は補足に下げる |
| 22〜28秒 | 応用 | AI応用映像へ切り替え、スケールを一段上げる |
| 28〜35秒 | ツッコミ | 一文の落差＋チャンネル登録。次回予告は入れない |

レーザー洗浄機の構成基準は `data/episodes/ai-viral-laser-cleaning-01.json` と `src/LaserCleaningShort.tsx`。磁性流体の視覚基準は `src/FerrofluidShort.tsx`。

## 事実とAI映像

- 制作ブリーフへ、確認日、直接URL、各出典が支える主張を書く。
- メーカーの用途説明は、そのメーカーが示す条件の範囲に限定する。
- AI映像を現場映像、実験記録、公式製品画像として扱わない。
- AI素材には `AI再現映像`、応用には `AIによる応用イメージ` を表示する。
- 一次資料がない数字や用途を、映像の迫力だけで断定しない。

## Google Flow用の2カット

### Cut 1: 現象

- 縦9:16、8秒、ワンカット、最初から現象が進行中。
- 決定的な変化を3.5〜5.5秒付近へ置く。
- 形状、穴、治具、手、装置を固定し、途中で増減させない。
- 上25〜30%を暗く単純にし、字幕安全域を作る。
- 焼き込み文字、音声、音楽、ロゴ、透かしを禁止する。

### Cut 2: 応用

- 対象の接写から実利用のスケールへ、ゆっくり引く。
- 人物や精密操作を増やさず、装置形状を安定させる。
- 科学図解はFlow内で生成せずRemotionで作る。
- 実地利用の証拠ではなく、応用イメージとして明記する。

## Suno BGM

- Instrumental only。歌詞、話し声、チャントを禁止する。
- 0秒からリズムを開始し、アンビエント導入を置かない。
- 現象区間は緊張感と編集用の空白、名称・疑問で半拍抜く。
- 仕組み区間はナレーションを邪魔しない精密な音数へ落とす。
- 応用でスケールを広げ、最後は明確にコミカルな音色へ切り替える。
- 決定音はBGMへ焼き込まず、RemotionのSEで同期する。

## VOICEVOX

- 男性の低めの声: 権威、固有名詞、仕組み、用途。
- 女性の明るい声: 驚き、疑問、言い換え、最後のツッコミ。
- 表示用漢字と読みを分離し、誤読しやすい語は読み欄をかなで書く。
- 固有名詞、数字、同音異義語は必ず聴いて確認する。
- 音声だけ直す場合も、最終ファイルを再正規化してデコード検査する。

## Remotionの画面基準

### バッジ

- シリーズバッジ: `top: 44〜45`, `left: 36〜38`。
- AI表示: `top: 48〜49`, `right: 34〜35`。
- バッジの下に主見出しを始め、上部カメラ／UIと競合させない。

### 上見出し

- 開始位置: `top: 170〜190`。
- 前振り: 58〜95 px、白、濃い縁と影。
- 主見出し: 103〜155 px、黄色、白の8〜10 px袋文字、濃い落ち影。
- 左右余白: 28〜38 px。
- 映像上へ直接置き、小さな黒い全面カードへ戻さない。
- 8文字以上の一行は実フレームで幅を確認する。

### 下の掛け合い字幕

- 標準: `width: 920`, `bottom: 245`, `fontSize: 47`。
- 中央寄せ、黒の半透明背景、上辺にアクセント色8 px。
- 2行字幕を基準とし、出典や補足と重ねない。

### 最終画面

- 背景映像を残し、1枚の半透明中央パネルを使う。
- 外枠: `top: 96`, `bottom: 108`, `left/right: 40`。
- `display: flex`, `justifyContent: center`, `alignItems: center` で縦軸を統一する。
- 順番は固有名詞、前振り、黄色のツッコミ、区切り、登録文、黄色ボタン、チャンネル名。

## 効果と音量

- 決定フレームだけに、画面揺れ、白フラッシュ、色変化、強いSEを集中する。
- 説明区間はバー、ゲージ、矢印、比較図を使う。
- BGMはナレーション中に下げ、名称、数字、オチの前後に間を作る。
- 完成音量は約 -16 LUFS、True Peakはおおむね -1.0〜-1.5 dBTPを目標にする。

## レンダー契約とQC

1. episode JSONとresolved JSONを同期する。
2. 専用Compositionを `src/Root.tsx` に登録する。
3. `ProductionTeam/handoffs/<episode>.render.json` を `ready` にする。
4. 共通コマンドでレンダー、正規化、ffprobe、全編デコード、代表フレーム抽出を実行する。

   ```powershell
   npm run finalize:handoff -- ProductionTeam/handoffs/<episode>.render.json
   ```

5. 冒頭、名称、疑問、仕組み、応用、CTAの静止画を原寸確認する。
6. 長文の切れ、上部カメラUI、右側Shortsボタン、下部説明欄との衝突を確認する。
7. 機械合格と、人の視聴確認を分けて記録する。

## YouTube SEOと投稿

- Analyticsで検索流入が大きい場合、検索語を削ってフィード専用タイトルにしない。
- タイトル順は `平易な矛盾 + 固有名詞 + なぜ／仕組み + 意外な結末 + #Shorts`。
- 概要欄の最初の2行で検索質問と回答内容を完結させる。
- 一次資料、AI免責、VOICEVOX、AI生成BGMを明記する。
- 公開ハッシュタグは関連性の高い3つに絞る。
- 投稿前にライブ予約一覧を取得し、同じ時刻に重ねない。
- 明示的な投稿許可なしにアップロードしない。
- 投稿後はID、URL、公開時刻、AI申告を `OperationTeam/uploads/` と報告書へ記録する。

## 最終チェック

- 冒頭0秒に結果が見える。
- 固有名詞が8秒以内に出る。
- 疑問と説明の声色が違う。
- AI表示と一次資料の区別が明確。
- 上見出し、下字幕、CTAが既存シリーズと同じ安全域。
- オチは一読で分かり、次回予告がない。
- 完成MP4、JSON、brief、handoff、QC、投稿情報が同じ内容を指す。
