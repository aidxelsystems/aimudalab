# Shorts再生回数予測とPDCA

## 目的

企画時点の期待と公開後の結果を比較し、題材、フック、尺、感情曲線、配信機会のどこで見込み違いが生じたかを学習する。予測は目標ではなく、現在のチャンネル状態を前提にした見積もりとする。

## 公開前に固定する値

各作品で次を記録する。

| 時点 | 弱気 | 基準 | 強気 |
|---|---:|---:|---:|
| 公開24時間 |  |  |  |
| 公開72時間 |  |  |  |
| 公開7日 |  |  |  |

- 弱気: フィード配信が弱い、または冒頭選択が既存中央値以下の場合。
- 基準: 保存済み実績と企画の強弱を合わせた最頻シナリオ。PDCAではこの値を使用する。
- 強気: 題材とフックが機能し、現状の上位帯を超えて配信が続く場合。

根拠として、比較対象の公開後経過時間、標本数、中央値、上位25%点、上位10%点、最大値を可能な範囲で残す。新形式は不確実性を広く取り、根拠なく1,000回以上を通常予測にしない。

確定値は企画引継ぎに加えて `../OperationTeam/data/view-forecasts.json` へ登録する。結果判明後は `forecast` を変更せず、`actuals` と `review` だけを更新する。

## 目標との分離

`予測`は起こりそうな値、`成功目標`は到達したい値である。成功目標が予測より高くてもよいが、同じ欄へ書かない。

## 公開後の記録

各判定時点で以下を追記する。

```text
実績:
基準予測:
絶対GAP = 実績 - 基準予測:
GAP率 = (実績 / 基準予測 - 1) × 100:
予測帯判定: 弱気未満 / 予測帯内 / 強気超過
Shown in feed:
視聴を選択した割合:
平均視聴時間・平均視聴率:
反応:
GAPの原因仮説:
次回変える1要素:
```

## 判断順序

1. Shortsとして正常に分類・配信されたか。
2. フィードへ表示されたか。
3. 表示後に視聴を選ばれたか。
4. 冒頭から最後まで維持されたか。
5. 高評価、コメント、共有、登録につながったか。

再生回数だけで内容の良否を断定しない。表示不足なら配信機会、選択率不足なら題材・タイトル・冒頭、維持率不足なら構成・尺・間、反応不足なら報酬・共感・共有理由を優先して検討する。
