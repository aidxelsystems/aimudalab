# OperationTeam

「AIのムダ遣いちゃんねる」(`@AIMudaLab`) の実績を分析し、再現可能な成長施策へ変換する運用チーム。

チャンネルの長期方針は `../CHANNEL_VISION.md` を正とし、現在はPhase 1「Shortsで認知と勝ち筋を探索」を最優先する。

## 起動方法

運用依頼は必ず `agents/operation-manager.md` から開始する。統括は対象期間と利用可能なデータを確認し、専門担当の分析を統合する。

データがない場合は推測で数値評価を行わない。以下の順で利用可能な情報を増やす。

1. `data/snapshots/` の保存済みスナップショット
2. YouTube Data APIの公開指標
3. YouTube Analytics APIの所有者指標
4. `data/imports/` に置かれたYouTube StudioのCSV

## 担当

- `agents/operation-manager.md`: 分析統括、品質監査、最終レポートの唯一の編集責任者
- `agents/data-analyst.md`: 収集、整形、欠損確認、比較期間の妥当性
- `agents/performance-analyst.md`: 初速、視聴効率、反応率、登録転換の分析
- `agents/content-strategist.md`: 題材、タイトル、構成、尺、シリーズ性の分析
- `agents/growth-planner.md`: 次週の企画と検証可能な実験計画

## 分析フロー

1. 統括が対象期間、投稿本数、目標を定義する。
2. データ担当が収集日時、タイムゾーン、欠損、指標の取得元を監査する。
3. パフォーマンス担当が直近7日と前7日、各動画の同じ公開後経過時間を比較する。
4. コンテンツ担当が上位・下位動画の題材、タイトル、構成、尺の差を仮説化する。
5. 成長担当が「仮説・変更点・成功判定」を1組にした実験を最大3件作る。
6. 統括が事実、解釈、提案を分離して週次レポートへまとめる。

BusinessTeamは週次レポートを事業化判断の入力として読む。OperationTeamは案件獲得の可否を決めず、視聴実績、登録転換、シリーズの再現性、データ欠損を事実として提供する。

## 必須ルール

- 絶対再生数だけで動画を評価せず、公開後の経過時間を揃える。
- 小標本では断定せず、「兆候」「仮説」と明記する。
- 相関を因果として扱わない。
- Shortsと通常動画を混ぜて平均しない。
- 削除、非公開化、投稿、コメント返信は自動実行しない。
- OAuthトークン、APIキー、個人情報をファイルやレポートへ書かない。
- 視聴者属性は集計値のみを扱い、個人の特定を試みない。
- 改善案は一度に最大3変数までとし、何が効いたか判定できる形にする。

## 週次レポート契約

レポートには必ず以下を含める。

```text
対象期間:
取得元と欠損:
要約:
主要KPI:
伸びた動画:
改善余地のある動画:
観測された事実:
解釈・仮説:
次週の実験（最大3件）:
次の企画候補:
継続／停止／保留:
```

各実験は次の形式にする。

```text
仮説:
変更する要素:
変更しない要素:
成功指標:
判定時点:
```

## 完了条件

- すべての数値に対象期間と取得元がある。
- 比較する動画の公開後経過時間が考慮されている。
- 事実と仮説が明確に分かれている。
- 次週のアクションが3件以内に優先順位づけされている。
- 成功判定が数値または明確な観察条件で定義されている。
